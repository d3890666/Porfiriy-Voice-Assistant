# Журнал изменений (Changelog)

## 0.0.112
- **Строгий перевод всех запросов на Gemini Live WebSocket API (`bidiGenerateContent`)**:
  - Полностью исключены REST-вызовы `generate_content` и любые подмены моделей. И текстовые ответы для Алисы (`response_modalities=["TEXT"]`), и аудиоответы для AirPlay (`response_modalities=["AUDIO"]`) генерируются через единый сессионный Live WebSocket с выбранной в настройках моделью (`gemini-3.8-live`).
  - Сохранены все оригинальные инструменты Home Assistant и Music Assistant без изменений.
- **Увеличение лимита WebSocket Home Assistant (`max_size=16MB`)**:
  - В `ha_api.py` для соединений WebSocket установлен лимит `16*1024*1024` байт, устранив ошибку `1009 message too big` при передаче больших реестров устройств.

  - **Добавление метода `ha_api.get_entities_prompt()`**: Устранено предупреждение `'HomeAssistantAPI' object has no attribute 'get_entities_prompt'`. Системный промпт теперь бесшовно получает список exposed-устройств умного дома и доступных действий Home Assistant.

## 0.0.109
- **Интеграция с Яндекс Станцией 2 (Quasar Bridge) через OpenAI API Gateway**:
  - **OpenAI-совместимый эндпоинт (`POST /v1/chat/completions`)**: Реализован сервис `backend/openai_service.py`, принимающий запросы от Quasar Bridge (рутованная Яндекс Станция 2). Поддерживает `POST /v1/chat/completions`, `POST /chat/completions`, `GET /v1/models` и CORS.
  - **Интеллектуальная идентификация ноды**: Сервер распознает источник запроса по URL (`?device=...`), заголовкам (`X-Device-Id`), персональному Bearer токену, имени модели или клиентскому IP адресу, а также автоматически регистрирует новые Яндекс Станции при первом обращении.
  - **Переключатель режима вывода на ноде (Dual Output Mode)**:
    - **Режим «🗣️ Голос Алисы (возврат текста)» (`alice_tts`)**: Gemini выполняет команды умного дома или поиск через Google Search, очищает текст от Markdown, эмодзи и спецсимволов (`sanitize_text_for_speech`) и возвращает лаконичный ответ в JSON OpenAI для озвучки Алисой.
    - **Режим «🎵 Голос Порфирия (AirPlay)» (`airplay`)**: Gemini синтезирует нативный аудиоответ Порфирия (голос Zephyr/Charon), аддон транслирует WAV-поток на настроенный AirPlay-плеер Станции (`media_player.station_2_airplay`), а в ответ Quasar Bridge отдается пустой текст, чтобы Алиса не перебивала голос Порфирия.
  - **Управление музыкой через Music Assistant**: По запросу пользователя модель или быстрый перехват команд вызывает службу `mass.play_media` (с фолбэком на `media_player.play_media`) с направлением звука на AirPlay-плеер Станции. Команды паузы, продолжения, стопа и переключения треков отрабатывают мгновенно.
  - **Глобальные настройки и порт LAN**: В `config.yaml` открыт порт `8000/tcp: 8000`. Вкладка «Мозг & Вейкворд» дополнена блоком настроек OpenAI API (включение, выбор порта, общий API-ключ, дефолтный AirPlay-плеер и памятка по URL для Quasar Bridge).
  - **Карточка Яндекс Станции и ручное добавление в Web UI**: Во вкладку «Флот колонок» добавлена фиолетовая карточка ноды Яндекс Станции с переключателем режима ответа, выбором плеера, персональным токеном и кнопкой тестового вызова. Добавлена кнопка «🟣 + Яндекс Станция» с модальным окном.
- **Синхронизация версий и кэш-бастеров**:
  - Версия аддона в `config.yaml` поднята до `0.0.109`.
  - Кэш-бастеры скриптов и стилей в `index.html` обновлены до `?v=0.0.109`.
- **Быстрая сборка, нативный MQTT Media Player и оптимизация Docker**:
  - **Восстановление мгновенной сборки (Docker Cache Restore)**: Удалена тяжелая системная зависимость `ffmpeg` из `apt-get` в `Dockerfile`. Это восстановило 100% совпадение слоев кэша Docker в Home Assistant — сборка и обновление аддона теперь снова занимают считанные секунды вместо 20+ минут.
  - **Нативный MQTT Media Player в Home Assistant**: В `mqtt_discovery.py` добавлена авто-регистрация стандартного компонента `media_player` для каждой подключенной колонки. Плеер автоматически появляется в карточке устройства Home Assistant рядом с громкостью и микрофоном, поддерживает команды управления (Play/Pause/Stop) и регулировку громкости без необходимости ручной настройки DLNA/UPnP.
  - **Команда Stop в прошивке ESP32**: В `onMessageCallback` добавлена обработка команды `{"type":"stop"}`, мгновенно возвращающая колонку в `STATE_IDLE`.

## 0.0.107
- **Энергетический VAD окончания речи, DLNA Media Player и Тонкая настройка звука**:
  - **Устранение затягивания диалога и самоперебивания (Server VAD & Cooldown)**: В `handle_pc_streamer` и серверный режим вейкворда внедрен энергетический детектор паузы речи (VAD) с автоматической инъекцией пакетов тишины в Gemini Live при фиксации паузы после фразы пользователя. Звуковой поток микрофона временно отсекается во время обработки (`thinking`) и воспроизведения речи (`speaking`), предотвращая акустическое самоперебивание. Введен 2-секундный кулдаун и обязательный сброс буфера `ww_engine.reset(client_mac)`.
  - **Тумблер авто-выравнивания микрофона (WebRTC Peak Limiter / AGC)**: В карточку ESP32 и локальный Web UI добавлен переключатель `mic_limiter_enabled` (Вкл/Выкл), сохраняемый в NVS-памяти ESP32 (`limiter_en`). Позволяет тестировать микрофон как с мягкой DSP-компрессией пиков, так и с чистым линейным усилением.
  - **Настройки звука в карточке ESP32**: В аккордеон тонкой настройки вынесены параметры: «Пауза конца фразы» (`silence_timeout_ms`: 300–2000 мс), «Порог голоса RMS» (`silence_threshold_energy`: 50–800) и «Ожидание команды» (`listen_timeout_s`: 3–15 с). Светодиоды оставлены только в групповых настройках, сетевые настройки — только в локальном Web UI платы.
  - **Интеграция DLNA Media Player (Music & Stream Bridge)**: Создан модуль `backend/dlna_player.py`, реализующий стандартный DLNA DMR (Digital Media Renderer) с авто-обнаружением через SSDP и ручным подключением по URL (`/dmr/<mac>/description.xml`). Позволяет проигрывать музыку, интернет-радио, подкасты и треки из Music Assistant на динамиках ESP32 через фоновое транскодирование в `ffmpeg` с автоматической приостановкой при вызове Порфирия. В `Dockerfile` добавлен `ffmpeg`.
- **Синхронизация прошивки и версий**:
  - Прошивка ESP32 обновлена до версии `0.0.107` (файл скомпилирован в `.pio/build/esp32-s3-devkitc-1/firmware.bin` и скопирован в `backend/firmware/firmware.bin`).

## 0.0.105
- **Универсальный шлюз действий Home Assistant (Universal HA Actions & Live Data Responses)**:
  - **Автоматическая поддержка сервисов с возвратом данных**: Порфирий теперь автоматически опрашивает реестр сервисов Home Assistant (`get_services`) и находит все действия, возвращающие данные (`response`, например `moscow_transport.get_arrivals`, прогноз погоды, события календаря и др.).
  - **Динамическое информирование модели**: В системный промпт Gemini автоматически передается секция `AVAILABLE HOME ASSISTANT DATA ACTIONS` с точным списком доступных действий, их описанием и входными параметрами (например `stop_id`, `routes`).
  - **Универсальный вызов `call_ha_action`**: `ha_api.call_ha_action` интеллектуально запрашивает ответ через WebSocket (`return_response=True`), извлекает payload и передает его в Gemini. Если действие является обычной командой без возврата данных (например `light.turn_on`), вызов прозрачно выполняется в стандартном режиме.
  - **Естественная озвучка без ложных щелчков реле**: При вызове действий, вернувших живые данные (например, время прибытия автобусов), звук щелчка реле (`SUCCESS_CHIME`) автоматически отключается, давая Gemini плавно и без помех озвучить результат голосом.
  - **Поддержка инструментов в сателлитах ПК**: В `handle_pc_streamer` добавлен полноценный цикл обработки `response.tool_call`, благодаря чему управление умным домом и запрос расписания работают как с колонок ESP32, так и с ПК-клиентов.
  - **Снято ограничение на обязательный `entity_id`**: В схеме `call_ha_service` параметр `entity_id` стал опциональным, добавлен универсальный контейнер `parameters` для произвольных аргументов.
- **Синхронизация версий и кэш-бастеров**:
  - Версия аддона в `config.yaml` поднята до `0.0.105`.
  - Кэш-бастеры скриптов и стилей в `index.html` обновлены до `?v=0.0.105`.

## 0.0.104
- **Устранение зависания ESP32 в THINKING (моргание жёлтым) и сбоя повторного вызова**:
  - **Сброс состояния после выполнения Tool Call**: после отправки ответа Home Assistant в Gemini сбрасывается флаг `first_audio_sent = False`, благодаря чему при ответе модели плата гарантированно получает команду `speaking` и включает яркий светодиод речи.
  - **Устранение зависания при внешнем медиаплеере**: если аудио выводится на Яндекс Станцию / HA медиаплеер, плата корректно переводится в `speaking` и возвращается в `idle` по завершении фразы, исключая застревание в янтарно-жёлтой пульсации.
  - **Устранение ложного отсечения речи длиннее 3.5 секунд**: сторожевой таймер воспроизведения на ESP32 теперь проверяет время последнего принятого аудиопакета (`millis() - last_audio_packet_time > 2500`) вместо времени входа в состояние. Длинные фразы больше не обрываются на середине.
  - **Разблокировка приема аудио в IDLE**: в `onMessageCallback` снята блокировка входящего PCM звука в режиме ожидания. При получении аудио от сервера колонка мгновенно активирует воспроизведение.
  - **Защита от аппаратного WDT-зависания I2S**: в `i2s_write` задан таймаут `pdMS_TO_TICKS(200)` вместо `portMAX_DELAY`.
  - **Защита от ложного перехода в офлайн при реконнекте**: в `DeviceManager` завершающийся сокет не помечает устройство как офлайн, если к серверу уже подключился новый сокет.
- **Синхронизация прошивки и кэш-бастеров**:
  - Прошивка ESP32 обновлена до версии `0.0.104`.
  - Кэш-бастеры скриптов и стилей обновлены до `?v=0.0.104`.
